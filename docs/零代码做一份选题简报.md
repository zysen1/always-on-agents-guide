# 让 Claude 明早交一张选题卡

适合已经能使用 Claude 定时任务的人。你需要一个支持此功能的付费方案、一个能由 Claude 访问的公开来源，以及一个你会去查看结果的位置。第一次只试一个来源；在你核对过链接之前，把输出保存在任务会话里。

## 先给它一份明确的工作

把下面这段贴进 Claude。方括号里的内容换成你的领域、读者和来源即可。也可以先保留示例，亲自跑一次。

```text
帮我设置一份工作日选题简报，北京时间每天早上 9 点运行。我的观众是想把 AI 工具用于日常工作的中文创作者。
先只读这个公开来源：https://github.com/langchain-ai/langgraph/releases 。忽略预发布和开发者个人动态。
找过去 24 小时有正式发布的条目，打开原链接核对。每次最多留一条，写清：
更新了什么；普通用户今天能验证的一个动作；做这个动作需要什么条件；原链接和发布日期。
你拿不准的效果改写成待验证的问题。如果无法读取来源，写“本轮读取失败”；读到但没有符合条件的更新，写“本轮无新增”。
若你能读到此前简报，按永久链接排重；读不到就明确提醒我。本轮结果只留在任务会话里，由我决定是否发布。
先把拟执行的时间、来源和输出格式给我。我确认后跑一次样例。
```

## 在哪里点

1. 在新版 Claude 的对话里描述任务和时间，核对它给出的时区、频率、来源与指令，然后点 **Schedule**。在仍显示 Cowork 的界面，从侧栏 **Scheduled → New task → Create with Claude** 进入。
2. 去 **Scheduled** 找到刚创建的任务。先按需运行一次，打开该次会话，点回它给的发布页，核对标题、日期和所说功能。若返回“无新增”，临时把窗口改成过去七天验收一次，再调回 24 小时。
3. 第二次跑同一窗口，看它能否读到历史，或者会把同一条更新再交一次。对“绝不能重复”的流程，使用仓库里的本地雷达，把稳定来源 ID 存进 SQLite。只在提示词里写“记住”无法替代持久化记录。
4. 想停时，在 **Scheduled** 暂停该任务。团队用户先核对管理员的云端设置；本地文件也要确认该任务能访问到。

截至 2026-11-27，帮助中心将定时任务列为付费功能，并说明云端运行、各端入口及组织配置。以上按官方界面说明编写；仓库实际运行的实验见本地雷达。 [Claude 定时任务帮助中心](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork)

## 两个可以直接换进去的任务

| 谁用 | 公开来源换成 | 收到什么才值得看 | 人来决定什么 |
| --- | --- | --- | --- |
| 做软件教程的人 | 自己常教的两个工具的官方更新页 | 界面或操作步骤有变化；给出这一步的原文依据与复测方法 | 是否补录教程 |
| 做产品运营的人 | 三个竞品的官方更新日志 | 有可试用的新功能；标出所需套餐、开关或预览资格 | 是否纳入团队选型 |

先验收一个动作：读者点开原链接，能自己确认这一期究竟更新了什么。能做到这一点，再加第二个来源。
