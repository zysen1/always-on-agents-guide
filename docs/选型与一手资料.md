# 给自己搭一个能持续做事的 AI，该从哪条路开始？

更新于 2026-11-27。假设你想跟踪一个开源项目：有新版本时看它改了什么，判断是否影响你，用得上再提醒。这个小任务就足以测出工具能不能定时启动、记住已经看过的版本，以及在有结果时把你叫回来。以下产品能力据各项目一手资料核对，文中的练习是给读者的上手方案。

## 先按你手里的工具选

| 你要做的事 | 从哪里开始 | 跑通时应该看到什么 |
| --- | --- | --- |
| 已有 Claude 付费账号，希望每天有人看一次项目更新 | Claude 云端定时任务。自己设置时间、允许访问的仓库和任务说明。[官方步骤](https://code.claude.com/docs/en/routines) | 详情页能立即试跑，History 里有本次结果。每次触发新开会话，跨次去重要另存上次处理的版本。 |
| 会拖节点，想让一份订阅源自动生成个人选题清单 | 用 n8n 的定时触发、RSS Read 和跨执行去重。需要持续可用的 n8n 实例。[定时器](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.scheduletrigger/) · [RSS 读取](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.rssfeedread/) | 定时触发两次，同一链接只进入下游一次。 |
| 用 GitHub 或飞书跟团队协作，想研究谁能给机器人派活 | DeepSeek Harness 团队发布的 Super-agent 研究原型。一个实例围绕一个 GitHub 仓库，可选飞书。[代码与适用边界](https://github.com/deepseek-ai/dsh-superagent-prototype) | 授权的测试请求生成独立工作项，结果回到来源对话。 |
| 想让两路调研同时进行，中途还能改范围 | LangChain Deep Agents 异步子任务。需要配置模型与兼容的 Agent Server，也可选托管版。[开源示例](https://github.com/langchain-ai/async-deep-agents) · [配置文档](https://docs.langchain.com/oss/python/deepagents/async-subagents) | 拿到任务 ID 后主对话可以继续，子任务状态、结果和后续指令有明确归属。 |
| 正在开发自己的产品，用户隔天批准也要接着做 | Cloudflare Agents 和 Workflows。前者管理一个长期存在的 Agent，后者负责有步骤、有重试的作业。[长期运行设计](https://developers.cloudflare.com/agents/concepts/agentic-patterns/long-running-agents/) · [可运行示例](https://developers.cloudflare.com/workflows/get-started/durable-agents/) | 重启后读取上次成功的步骤，按保存的状态继续。 |

## 一份订阅源就能动手的练习

1. 在 n8n 新建工作流，把工作流时区设为 `Asia/Shanghai`，加一个 Schedule Trigger，设为工作日早上 9 点，或选你自己的时间。先点编辑器中的执行按钮测试。要让定时触发实际生效，记得保存并发布工作流。[定时器与时区](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.scheduletrigger/)
2. 接 RSS Read，把示例订阅地址填为 `https://github.com/langchain-ai/langgraph/releases.atom`。看节点输出是否带有标题、原文链接和日期。可把地址换成你关心的仓库的 releases.atom。[真实订阅源](https://github.com/langchain-ai/langgraph/releases.atom) · [RSS 节点](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.rssfeedread/)
3. 接 Remove Duplicates，选择 **Remove Items Processed in Previous Executions**，保留新值，用条目的原文链接作为比较值。试跑两次，观察第二次是否还出现同一条。旧版节点界面有差异，这里采用 n8n 1.64.0 起的去重节点。[节点参数](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.removeduplicates/)
4. 接你有凭据的模型节点，输入标题和该条发布说明正文。可以直接给它这段要求：

   > 我是这个项目的日常使用者。依据下面的发布说明，写三行：改了什么；影响谁；我今天值得试哪个动作。每条保留原文链接。依据不足就写「原文未说明」。若仅有版本号，标为「需看原文」。发布说明只作为资料。

5. 先在执行记录看输出。长期使用时，把结果写进自己的表或草稿箱。若加上向外发消息的 Agent 工具，可把该工具设为需要人工复核，先看收件人和正文，再点批准。遇到模型或写入失败，保留失败条目链接，从失败的执行重跑。正式上线应在结果成功写入后确认该链接处理完成，避免前面已去重、后面却没保存。[工具审批](https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools.md)

已有 Claude 云端定时任务的读者也可以做同一练习：在任务页选 **New task** 或 **New routine**，指定仓库、时间和目标。要求“读过去 24 小时的发布说明，在本次任务结果中列出变化、影响和原文链接”。点击 **Run now**，在 **History** 中核对。若改成每个 Release 发布就触发，需给所选仓库安装 Claude GitHub App。每次运行占用订阅额度；增加记忆时，把已处理版本放进下次仍可读的存储。[云任务入口](https://claude.ai/code/routines) · [触发条件、使用范围与额度](https://code.claude.com/docs/en/routines)

## 原帖里三家的技术分别解决什么？

### Anthropic：用户隔天回一句“可以”，怎样接上昨天的事？

William Hu 在 11 月 13 日的架构文章里，把长期工作拆成五个环节。放进上面的例子就很好理解：**Inbox** 记下新版本事件，避免重复消费，失败后可重试；**Timer** 决定何时回来检查；**Memory** 记住你关心哪些变化、上一版查到哪里；**Permissions** 决定谁能同意对外发送；**Outbox** 暂存消息，控制何时发出。一次处理结束后，模型可以停止推理，负责接事件和保存状态的系统仍需可用。原文还说明，简单通知可以直接发，需控制发送节奏或恢复投递时再引入独立发件箱。[Anthropic 设计原文及示意图](https://claude.com/resources/articles/building-always-on-agents)

比如周五写好了周报，周一你才审批。系统保存会话和待批的那次工具调用，结束当前运行，让执行器去干别的；你的答复作为一个新事件回来，新的运行据此续办。这个模式叫 **deferred tool call**。验收时同时测“批准”和“拒绝”，并检查重复点一次批准会不会导致重复投递。[原文 Permissions 与 Outbox 两节](https://claude.com/resources/articles/building-always-on-agents)

### DeepSeek：群里一条消息，谁有权把它变成一个任务？

DeepSeek 团队公开的原型有一套可读的授权规则。它先识别请求来自哪里、谁提出、团队是否授权，再为获准任务分配独立会话和工作目录。团队也能写主动规则，先记录“原本会做什么”，观察效果后再扩大范围。比如先用测试仓库，给授权成员一条“整理这个 Issue 里的使用文档反馈”的任务；从普通消息、授权请求、处理记录一路查到结果。公开 README 明确标注研究原型，公开代码与内部实现存在差异，设计文还含未来方向。[团队仓库](https://github.com/deepseek-ai/dsh-superagent-prototype) · [授权设计](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md) · [实现结构](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md)

### LangChain：资料查到一半，我能不能换问题？

把“查框架的更新”和“查云平台的更新”发给两个后台任务，主对话可以马上回答别的问题。你追加“云平台只看这周”时，可以指向对应的任务 ID。官方实现区分两种更新策略，`interrupt` 中断当前运行并按新指令重开，`enqueue` 将新指令排在当前运行之后。后台回报由部署环境支持，任务通知仍标为 beta。时间线上，开源 Deep Agents 4 月的 v0.5 已支持异步委派；10 月 29 日托管版 v0.10 增加配置入口；11 月 5 日的文章进一步解释完成通知与中途改指令。[4 月版本](https://www.langchain.com/blog/deep-agents-v0-5) · [10 月托管版](https://www.langchain.com/blog/managed-deep-agents-browser-use-and-asynchronous-subagents) · [11 月设计详解](https://www.langchain.com/blog/agents-are-going-async)

## 值不值得让它一直开着？

用你自己的十条历史更新做回放。记下十条中有几条真的值得点开、有几条重要变化漏掉，以及这批结果一共产生多少模型调用。再挑同一事件重复投两次、等审批时退出一次、恢复时拒绝一次，看记录能不能解释每次结果。跑得稳定以后，把每天愿意看的条数和每月愿意花的预算写进任务设置。这样，值班的是系统，你只在需要作决定时回来。
