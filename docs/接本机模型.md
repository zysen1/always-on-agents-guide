# 从规则草稿到模型选题卡

雷达的“待审”表示一条来源进入了候选清单。这里再把一条候选送给你自己的模型，让它建议拍摄角度。给模型核对过的材料，结果会比只给一个英文标题具体得多。

## 跑一张卡

准备一个已启动的本机 OpenAI 兼容聊天服务，例如在 LM Studio 中加载支持中文的对话模型并启动本机服务器。准备好服务面板列出的模型 ID。脚本默认连接本机 1234 端口，可用 `--port` 改动。它不会爬取原文，请先点开原链接，将核对过的事实放在摘记里。

在仓库根目录执行下面三条。示例使用独立的排练数据库；把最后一行的模型 ID 换成你机器上显示的名字。

```sh
python3 demo/radar.py --db ./rehearsal.sqlite3 sample
python3 demo/radar.py --db ./rehearsal.sqlite3 export --state pending > pending.json
python3 demo/local_brief.py --model "你的模型ID" --notes demo/notes-example.txt < pending.json
```

Windows PowerShell 可把最后两行合为一条管道。先设置 `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)`，让中文按 UTF-8 传递。

```powershell
py -3 demo/radar.py --db ./rehearsal.sqlite3 export --state pending | py -3 demo/local_brief.py --model "你的模型ID" --notes demo/notes-example.txt
```

程序默认取导出中的第一条。一次有多条时，先看导出的编号，再用 `--id 1` 明确指定。提供的摘记必须对应所选来源。支持关闭推理的模型可以加 `--no-thinking`，避免简短任务的输出预算都耗在推理上；如果服务不支持这个选项，省略即可。生成的草稿打印在终端，可重定向到自己的文本文件。它不会修改选题审核状态。

## 这期实际跑出的结果

拍摄时使用一台 Mac 的本地 LM Studio，用 27B 中文对话模型处理 Anthropic 文章的标题、原链接与已核对的摘记。模型的第一句是：

> 选题：演示“审批挂起”机制：保存动作与状态后释放进程，回复后恢复执行。

这句话给了我们一个具体镜头：关掉工作台再打开，找到刚才的待审稿。本地雷达演示的是 SQLite 保存和恢复草稿；Anthropic 描述的架构还包括保存工具调用和恢复模型会话。录制时分别展示才能看到两者各自做到了哪一步。

第一次实验直接给标题，得到的是“拆解长时运行 Agent 的核心设计逻辑”这一类宽泛选题。加入核对过的公开摘记后才有了上面的动作。模型随采样与输入可能给出不同结果。导出的链接由程序从原事件附上，录制或发布前请回原文核对。
